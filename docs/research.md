# Primary-source research and design rationale

Reviewed2026-10-14 by Jason Stys. Sources inform implementation; this is not a certification mapping.

- [NIST SP800-61Rev3](https://csrc.nist.gov/pubs/sp/800/61/r3/final): incident response as part of cybersecurity risk management. This lab adds preserved evidence and reviewable handling history; it does not implement a full organizational response program.
- [NIST SP800-86](https://csrc.nist.gov/pubs/sp/800/86/final): forensic techniques in IT incident investigation, with explicit management/legal/organizational context. Its2006publication is background guidance, not a new mandatory rule or an all-inclusive legal workflow. The code intentionally does not claim court admissibility.
- [SQLite transactions](https://www.sqlite.org/lang_transaction.html), [atomic commit](https://www.sqlite.org/atomiccommit.html), [foreign keys](https://www.sqlite.org/foreignkeys.html): one write transaction for bytes/events/provenance, per-connection foreign-key enablement and rollback. Requested synchronous commits do not replace measured process-kill/power-loss tests on your actual storage.
- [Python datetime](https://docs.python.org/3/library/datetime.html): aware timestamps distinguish explicit instants from ambiguous naive wall times. The project intentionally accepts a narrower microsecond known-offset subset rather than assuming arbitrary ISO strings are safe or local time is UTC.
- [OWASP CSV injection](https://owasp.org/www-community/attacks/CSV_Injection): formula-like cells can be dangerous in spreadsheets. Export minimizes fields and applies a plain-text prefix guard; it is not a generic spreadsheet sanitizer for every consumer.
- [RustCrypto sha2](https://docs.rs/sha2/0.11.1/sha2/): use the established incremental hash implementation, no homegrown SHA256. New0.11output uses byte-array formatting rather than relying on an older LowerHex implementation; known vectors and cross-language oracles test the result.
- [Cargo locked builds](https://doc.rust-lang.org/cargo/commands/cargo-build.html), [cargo test](https://doc.rust-lang.org/cargo/commands/cargo-test.html), [RustSec cargo-audit](https://github.com/RustSec/rustsec/tree/main/cargo-audit): exact reviewed lock graph/compiler, measured test execution and advisory checks. Tool version0.22.2 was checked against the official crates.io API before publication. No vulnerability ignores.
- [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions): current artifact occupancy and accrued billing differ. Usage can lag6–12hours; cleanup cannot undo accrued GB-hours. This repo's workflows never upload artifacts or enable Actions caches; checking storage does not authorize deletion.

Inferences/design choices: BLOB+SQLcommit is simpler than cross-resource atomicity for bounded local cases; field exclusion is more predictable than attempting to regex-redact arbitrary raw messages; an external prefix anchor makes the hash-chain trust limit testable. These are project decisions, not statements that a standard endorses this exact design. No external datasets/private logs were used.
